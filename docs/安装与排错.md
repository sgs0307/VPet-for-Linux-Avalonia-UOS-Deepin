# 安装与排错

## 安装流程

```bash
./scripts/build.sh      # 构建并发布到 ./publish（自动复制桌宠资源）
./scripts/install.sh    # 安装到 ~/.local/share/vpet 并生成桌面快捷方式
```

安装脚本会做四件事：

1. 把 `publish/` 整个拷到 `~/.local/share/vpet`（含桌宠资源 `mod/`）
2. 生成写死 dotnet 路径的启动器 `~/.local/share/vpet/vpet.sh`
3. 安装图标到 `~/.local/share/icons/hicolor/256x256/apps/vpet.png`
4. 生成桌面快捷方式 `~/Desktop/VPet.desktop`（中文桌面为 `~/桌面`）与应用菜单项

桌面快捷方式沿用原版 VPet 图标（`assets/icon/vpet.png`，320×320）。

## 手动运行

```bash
~/.local/share/vpet/vpet.sh
```

## 卸载

```bash
./scripts/uninstall.sh
```

## 常见问题

### 用 sudo / 其他用户装完后文件属主不对

安装目录或桌面文件属主是 root 时，普通用户可能无法修改或启动：

```bash
sudo chown -R $USER:$USER ~/.local/share/vpet ~/Desktop/VPet.desktop \
  ~/.local/share/applications/vpet.desktop
```

### 双击桌面图标没反应

1. 先在终端跑一次 `~/.local/share/vpet/vpet.sh`，看报错；
2. Deepin/UOS 要求桌面文件「可信任」：右键图标 → 属性 → 勾选「允许执行」，
   或执行 `gio set ~/Desktop/VPet.desktop metadata::trusted true`；
3. 确认 `chmod +x` 已生效（`install.sh` 已自动处理）。

### 提示未找到 dotnet

安装时会把当时探测到的 dotnet 路径写进启动器。若之后 SDK 换位置，
用 `VPET_DOTNET=/新路径/dotnet ./scripts/install.sh` 重装，或改 `vpet.sh` 里的 `DOTNET_BIN=`。

### 宠物不动 / 没有动画

说明没找到桌宠资源。检查 `~/.local/share/vpet/mod` 是否存在：

```bash
ls ~/.local/share/vpet/mod
```

为空则用 `VPET_MOD_SRC=/path/to/mod ./scripts/build.sh` 重新构建后重装
（桌宠资源来自上游 VPet 仓库的 `VPet-Simulator.Windows/mod`，体积约 1GB，未纳入本仓库）。

### 鼠标穿透不生效

穿透依赖 X11 的 XShape 扩展。程序按**实际渲染后端**判断：
`DISPLAY` 存在（含 Wayland 桌面下的 XWayland）就走完整 X11 能力；
只有完全无 `DISPLAY`（纯 Wayland 会话）才降级为小窗、关闭穿透。

检查日志：启动时若打印「检测到 Wayland 会话, 鼠标穿透不可用(协议限制), 已降级」，
说明运行环境的 `DISPLAY` 为空，在 X11/XWayland 会话下启动即可恢复穿透。

### 右键菜单点不动

右键菜单需要在窗口真正完成布局后重算 X11 输入区域，程序已挂 `LayoutUpdated` 处理。
若仍异常，检查是否运行在无 DISPLAY 的降级模式（见上一条）。

### 无法拖动

拖动依赖全屏窗口内的画布移动。若窗口被降级成宠物大小的小窗，可移动区间会退化成 0。
确认运行环境有 `DISPLAY`，日志中不应出现 Wayland 降级提示。

### 想看运行日志

启动器默认前台输出，直接在终端运行即可：

```bash
~/.local/share/vpet/vpet.sh 2>&1 | tee ~/vpet.log
```
