# 发布流程（可复用 SOP）

> 本文是一份**模板**，把 `<X.Y.Z>` 换成你的版本号就能直接照做。
> 配套脚本：`scripts/release.sh`（一键发版）、`scripts/package-release.sh`（只打包）。
> 第一次发布请先做完 [§1 一次性配置]，之后每个版本只看 [§2 版本发布清单]。

---

## 0. 一页速查

```bash
cd VPet-Avalonia-UOS
VER=1.3.2                       # ← 改这里
git pull                        # 确保是最新

# 1) 手写 CHANGELOG 顶部条目 + docs/RELEASE_NOTES-v$VER.md（脚本不替你编内容）
# 2) 一条命令跑完：改版本 → 构建 arm64/x64 → 打包 → 提交 → tag
./scripts/release.sh --version $VER -m "一句话说明"

# 3) 推送
git push origin main && git push origin v$VER

# 4) 网页发 Release：粘贴 RELEASE_NOTES，上传 dist/ 里的包
```

装了 `gh` 的话，第 3、4 步合并：

```bash
./scripts/release.sh --version $VER -m "一句话说明" --push --release
```

## 1. 一次性配置

### 1.1 创建仓库

1. <https://github.com/new>
2. 名字随意（本文以 `VPet-Linux-Avalonia` 为例），选 **Public**
3. ⚠️ **不要勾** `Add a README / .gitignore / license` —— 本地已有，勾了会冲突
4. Create repository

### 1.2 认证（二选一，配一次长期有效）

**A. Personal Access Token（推荐）**

- <https://github.com/settings/tokens> → Generate new token (classic)
- 勾 `repo` 权限，Expiration 90 天
- 生成后立刻复制（只显示一次）

```bash
git remote add origin https://github.com/<用户名>/VPet-Linux-Avalonia.git
git config --global credential.helper store     # 可选：省得每次输
```

第一次 `git push` 时用户名填账号，**密码填 token**。

**B. SSH key**

```bash
ssh-keygen -t ed25519 -C "你的邮箱"
cat ~/.ssh/id_ed25519.pub          # 整行复制到 https://github.com/settings/keys
git remote add origin git@github.com:<用户名>/VPet-Linux-Avalonia.git
```

### 1.3 提交身份

```bash
git config user.name  "你的名字"
git config user.email "你的GitHub邮箱"       # 与账号一致才会显示头像
```

已经提交过的话改历史身份：

```bash
git commit --amend --reset-author --no-edit
git tag -f -a v<当前版本> -m "v<当前版本>"
```

### 1.4 （可选）装 gh CLI

```bash
gh auth login          # GitHub.com → HTTPS → 浏览器授权
```

有 `gh` 才能用 `--release` 自动建 Release、断点续传上传大附件。

### 1.5 国内网络

`git push` 卡住或报 `Failed to connect to github.com port 443` 时给 git 挂代理：

```bash
git config --global http.proxy  http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
# 取消：git config --global --unset http.proxy
```

> `api.github.com` 通常直连可用，`github.com` 容易超时 —— 浏览器能打开仓库页面 ≠ `git push` 能通。

## 2. 版本发布清单

按顺序做，每步都有验收标准。

### 2.1 整理内容

- [ ] `CHANGELOG.md` 顶部加一节：

  ```markdown
  ## [X.Y.Z] — YYYY-MM-DD

  <一句话主题：这次补了什么/修了什么>

  ### 新增 / 修复 / 变更
  - ...
  ```

- [ ] 新建 `docs/RELEASE_NOTES-v<X.Y.Z>.md`（Release 正文，面向**下载用户**而不是开发者：
      先说下载哪个包、怎么装，再说改了什么）
- [ ] 自检日志丢进 `docs/verify-v<X.Y.Z>.log`（有实机验证才写，没有就别假装有）

### 2.2 跑自检

```bash
# 轻量模式（低内存机器必用，跳过多屏切换这类吃内存的项）
HOME=/tmp/vpet-test DOTNET_ROOT=$HOME/dotnet \
  VPET_SELFTEST=1 VPET_SELFTEST_LIGHT=1 \
  ./publish/VPet-Avalonia.App 2>&1 | tee docs/verify-v<X.Y.Z>.log
```

- [ ] 所有 `[TEST]` 行没有 `False` / 异常数对不上
- [ ] 日志末尾是 `[TEST] 自检结束`（不是 `Out of memory.`）

### 2.3 发版

```bash
VER=<X.Y.Z>
./scripts/release.sh --version $VER -m "一句话说明"
```

脚本做这些（`--dry-run` 可先看）：

| 步骤 | 动作 | 注意 |
|---|---|---|
| 1 | 写 `VERSION`、改 README 版本徽章 | CHANGELOG 不代写 |
| 2 | `dotnet publish -r linux-arm64` → `dist/_arm64` | 低内存统一 `-m:1` + GC 堆上限 |
| 3 | 交叉编译 `-r linux-x64` → `dist/_x64` | 需联网取 runtime pack，脚本已带 `--source` |
| 4 | `package-release.sh` 打 4 个包 | full 约 990 MB / nomod 约 9 MB |
| 5 | `git commit` + `git tag -a v$VER` | 工作区必须干净 |
| 6 | 可选 `--push` / `--release` | 没配 remote 时跳过 |

- [ ] 脚本最后打印的产物列表里有 4 个 `.tar.gz` + 2 个 `sha256.txt`

### 2.4 验包（重要，别省）

打包脚本可能因为路径、符号链接、漏挂 mod 出问题，**发之前自己解压装一遍**：

```bash
mkdir -p /tmp/pkgtest/home && cd /tmp/pkgtest
tar xzf ~/…/dist/VPet-UOS-v$VER-linux-arm64-nomod.tar.gz
cd VPet-UOS-v$VER
ls                                   # 应有 publish/ scripts/ assets/ docs/ README.md VERSION LICENSE
HOME=/tmp/pkgtest/home VPET_DOTNET=$HOME/dotnet ./scripts/install.sh
```

- [ ] 解压后层级是 `VPet-UOS-v$VER/publish/...`（`install.sh` 靠这个路径）
- [ ] `install.sh` 没报错，`~/.local/share/vpet/` 下有 `VPet-Avalonia.App`、`vpet.sh`
- [ ] full 包额外确认资源齐全：

  ```bash
  tar -tzf dist/VPet-UOS-v$VER-linux-arm64-full.tar.gz | grep -c 'publish/mod/.*\.png$'
  # 应等于源目录的 png 数量：find publish/mod -name '*.png' | wc -l
  ```

### 2.5 推送

```bash
git push origin main
git push origin v$VER
```

- [ ] 仓库首页 README 渲染正常，三张截图都在
- [ ] Tags 页面能看到 `v$VER`

### 2.6 发 Release

网页：仓库 → 右侧 **Releases** → **Draft a new release**

1. **Choose a tag** 下拉里选 `v$VER`（推送过才在列表里）
2. **Title**：`v$VER — <一句话>`
3. **Describe**：粘贴 `docs/RELEASE_NOTES-v$VER.md` 全文（支持 Markdown）
4. **Attach binaries**：拖入 `dist/VPet-UOS-v$VER-linux-*.tar.gz` 和 `*-sha256.txt`
5. **Publish release**

或用 gh：

```bash
./scripts/release.sh --version $VER -m "一句话" --push --release
# 或单独建：
gh release create v$VER --title "v$VER — 一句话" \
  --notes-file docs/RELEASE_NOTES-v$VER.md \
  dist/VPet-UOS-v$VER-linux-*.tar.gz dist/VPet-UOS-v$VER-linux-*-sha256.txt
```

> **990 MB 上传很慢**（10 Mbps 上行约 15 分钟，断了整个重传）。稳妥做法：
> 先传两个 `-nomod`（合计 18 MB）发布，然后 Edit → 再补两个 full 包（编辑时已上传的附件不会重传）。

- [ ] Release 页面能下载，附件大小与本地一致
- [ ] 正文里的表格、代码块渲染正常（不是一团乱码）

### 2.7 验收

- [ ] 换台机器/清空缓存，按 README 的「方式一」走一遍能不能装上
- [ ] `sha256sum -c` 通过

## 3. 只做打包（不发版）

改了代码想自己装机验证，不需要走完整发版：

```bash
./scripts/build.sh                       # 含 mod，输出到 publish/
VPET_SKIP_CLEAN=1 ./scripts/install.sh   # 覆盖安装，保留存档
```

只想要一个可分发的包：

```bash
./scripts/package-release.sh --src dist/_arm64 --arch arm64 --mod-from publish/mod
./scripts/package-release.sh --src dist/_x64   --arch x64   --mod-from publish/mod --no-mod
```

参数含义：

| 参数 | 作用 |
|---|---|
| `--src` | 程序目录（默认 `publish/`；`--arch x64` 时自动用 `dist/_x64`） |
| `--arch` | 包名里的架构标识，不给就按 apphost 的 ELF 头自动判断 |
| `--mod-from` | 桌宠资源从哪取（资源与架构无关，可以复用 arm64 那份） |
| `--no-mod` | 强制排除 mod，只打 nomod |

## 4. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `release.sh` 报「工作区不干净」 | 有未提交改动 | 先 `git add -A && git commit`，或 `git stash` |
| 报「tag vX.Y.Z 已存在」 | 重复发同一版 | `git tag -d vX.Y.Z`（已推送则 `git push origin :refs/tags/vX.Y.Z`） |
| `error NU1101: Unable to find package Microsoft.NETCore.App.Host.linux-x64` | NuGet 只配了离线源 | 交叉编译要带 `--source https://api.nuget.org/v3/index.json`（脚本已内置） |
| `CS0579: Duplicate 'TargetFrameworkAttribute'` | 给 `dotnet publish` 传了自定义 `BaseIntermediateOutputPath` | 别传，让 obj 按 RID 自己分子目录 |
| 打包报「文件在我们读入之前被删除了」 | 暂存目录里用了**相对路径**的符号链接 | 先把 `--src` 转成绝对路径（脚本已处理） |
| 打包含 `rm -rf` 被安全删除拦截 | 暂存目录文件数超阈值 | 用 `find -delete` 逐个删（脚本已处理） |
| `git push` 403 / Authentication failed | token 过期或权限不足 | 重新生成，密码位置填 token 不是账号密码 |
| `git push` 卡住无响应 | github.com 直连不通 | 挂代理（见 §1.5） |
| Release 附件上传失败 | 单附件超 2 GB，或网络中断 | full 包 990 MB 在限内；断了改用 `gh release upload --clobber` |
| 下载后 `install.sh` 说找不到 dotnet | dotnet 在非标准路径 | `VPET_DOTNET=/path/to/dotnet ./scripts/install.sh` |
| 装上后双击没反应 | 启动器把输出写进了日志 | 看 `~/.local/share/VPet/vpet.log` |
| 提交在 GitHub 上不显示头像 | `user.email` 与账号不一致 | 按 §1.3 改 |

## 5. 撤回与补救

| 场景 | 操作 |
|---|---|
| Release 正文写错 / 少传附件 | Releases → 该版本 **Edit** → 改完 Update（tag 不用动） |
| 附件传错，要换 | Edit → 删掉旧附件 → 重新上传；或 `gh release upload v<版本> <文件> --clobber` |
| 整个 Release 不要了 | Releases → Delete；需要连 tag 一起删：`git push origin :refs/tags/v<版本>` + `git tag -d v<版本>` |
| 提交推错了（还想保留） | `git revert <sha>` 再推一个新的 |
| 提交里混进大文件 | `git rm --cached <路径>`，写进 `.gitignore`，再提交。**已推送的历史无法真正瘦身**，要么接受，要么 filter-repo 重写（会改变所有 commit hash，需通知协作者） |
| 工作区丢了改动 | `git reflog` 找回来 |

## 6. 附录：本项目的固定约定

### 6.1 什么进仓库、什么不进

| 路径 | 进 git | 说明 |
|---|---|---|
| `src/` | ✅ | 四个 Avalonia 工程，约 500 KB 源码 |
| `docs/` `assets/` | ✅ | 文档与截图（截图单张 <400 KB） |
| `scripts/` `packaging/` | ✅ | 构建/安装/打包脚本 |
| `publish/` | ❌ | 发布目录，`.gitignore` 已排除 |
| `dist/` | ❌ | Release 包，同上 |
| `bin/` `obj/` | ❌ | 构建中间产物 |
| `mod/`（1.1 GB 美术资源） | ❌ | 版权归原作者，只在 Release 附件里分发 |

> 仓库 `.git` 目前 1.9 MB，克隆很快。**任何一次误提交大文件都会永久留在历史里**，推之前用
> `git status --short` 和 `git diff --cached --stat` 各扫一眼。

### 6.2 体积预算（v1.3.1 实测）

| 产物 | 大小 |
|---|---|
| `*-linux-arm64-full.tar.gz` | 990 MB |
| `*-linux-x64-full.tar.gz` | 990 MB |
| `*-nomod.tar.gz` | 8.7 MB（arm64）/ 9.3 MB（x64） |
| 源码仓库 `.git` | 1.9 MB |

full 包里 6495 个文件是桌宠帧图（6349 张 png），png 已压缩，再压收益很小 —— 所以打包用
`gzip -1`，速度比体积重要。

### 6.3 架构说明

- **x64**：统信 UOS / Deepin 主流架构，用户最多
- **arm64**：信创机器（鲲鹏 / 飞腾），开发机就是这台
- x64 是**交叉编译**产物，本机跑不了，只能验证「文件齐全 + ELF 头正确」；
  arm64 包做过真机自检。发版说明里不要写「x64 已实机验证」

### 6.4 许可证

上游 VPet 是 Apache-2.0，必须保留 `LICENSE` 和 README 里的上游链接。
宠物美术资源不放仓库，Release 里随包分发属合理使用，但 README 要写明版权归原作者。
